# 8. Give Parent Directory Traverse Permission

Target project nested path:

```text
/home/ai_root/Project/Safty_Automation_Website
```

এই path-এ পৌঁছানোর জন্য parent directories-এ শুধু traverse permission প্রয়োজন।

### `/home/ai_root`

```bash
sudo setfacl -m u:sumon_dev:x /home/ai_root
```

### `/home/ai_root/Project`

```bash
sudo setfacl -m u:sumon_dev:x /home/ai_root/Project
```

এতে `sumon_dev` parent directories traverse করতে পারবে।

কিন্তু অন্য files/folders browse করার জন্য প্রয়োজনীয় read permission থাকবে না।


# 10. Give Access to Existing Project Files

Project-এর ভিতরে আগে থেকে থাকা files/folders-এর জন্য recursive ACL:

```bash
sudo setfacl -R -m u:sumon_dev:rwX /home/ai_root/Project/Safty_Automation_Website
```

এখানে:

```text
-R
```

মানে recursive।

```text
rwX
```

মানে:

* Files → read + write
* Directories → read + write + traverse
* Existing executable files → execute permission preserve/allow

---

# 11. Default ACL for Future Files

এটি খুব গুরুত্বপূর্ণ।

Developer ভবিষ্যতে project-এর ভিতরে নতুন file/folder তৈরি করলে ACL automatically inherit করার জন্য:

```bash
sudo setfacl -d -m u:sumon_dev:rwx /home/ai_root/Project/Safty_Automation_Website
```

Existing subdirectories-এর জন্যও default ACL set:

```bash
sudo find /home/ai_root/Project/Safty_Automation_Website -type d \
  -exec setfacl -m d:u:sumon_dev:rwx {} \;
```

এতে future-created files/folders-এর উপর developer-এর access বজায় থাকবে।

# 22. Docker Security Warning

`docker` group-এ user add করলে user কার্যত Docker daemon-এর মাধ্যমে highly privileged/root-equivalent operations করতে পারে।

অর্থাৎ:

```bash
sudo usermod -aG docker sumon_dev
```

একটি security-sensitive permission।

তাই এটি trusted developer-এর জন্য ব্যবহার করা উচিত।

তোমার internal development/deployment server-এর জন্য এটি practical।

Strict isolation প্রয়োজন হলে Rootless Docker বা আরও শক্ত container/security boundary বিবেচনা করতে হবে।

# 30. Complete Setup Commands

```bash

sudo setfacl -d -m u:sumon_dev:rwx \
/home/ai_root/Project/Safty_Automation_Website

# 8. Default ACL for existing subdirectories
sudo find /home/ai_root/Project/Safty_Automation_Website -type d \
  -exec setfacl -m d:u:sumon_dev:rwx {} \;

# 9. Docker access
sudo usermod -aG docker sumon_dev
```

# 3. Why User Deletion Initially Failed

এর অর্থ user-এর কোনো active shell/session/process এখনো running ছিল।

বিশেষ করে VS Code Remote SSH ব্যবহার করলে নিচের ধরনের process থাকতে পারে:

* SSH session
* Bash shell
* `systemd --user`

* VS Code Server

* অন্যান্য user-level services

# 5. Delete User and Home Directory

যদি এগুলো `/home/shumon`-এর মধ্যে থাকে।

> **Important:** `userdel -r shumon` `/home/ai_root/Project/Safty_Automation_Website` delete করবে না। এটি শুধুমাত্র `shumon` account এবং তার home directory remove করে।
