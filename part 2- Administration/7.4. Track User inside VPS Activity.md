# Ubuntu VPS — `shumon` Developer User Activity Tracking & Audit

## 1. Objective

এই document-এর উদ্দেশ্য হলো Ubuntu VPS-এ developer user **`shumon`** কী কী activity করছে তা track এবং audit করা।

Developer user:

```text
shumon
```

Server:

```text
Ubuntu 22.04 LTS
```

Admin:

```text
ai_root
```

Project:

```text
/home/ai_root/Project/Safty_Automation_Website
```

---

# 2. What Should Be Tracked?

`shumon` user-এর ক্ষেত্রে নিচের activity track করা হবে:

* SSH login/logout
* Login time
* Login source IP
* Active sessions
* `sudo` commands
* Shell commands
* Process execution
* Project file changes
* Project directory access
* ACL permission changes
* Docker commands
* Git activity
* Node/npm commands
* VS Code Remote SSH activity
* User creation/deletion
* Permission changes
* Important system changes

> **Important:** কোনো single log সব activity capture করবে না। তাই SSH logs + sudo logs + shell history + `auditd` একসাথে ব্যবহার করা সবচেয়ে ভালো।

# 3. Check `shumon` User Information

```bash
id shumon
getent passwd shumon
groups shumon
```

UID check:

```bash
id -u shumon
```

Username এবং UID দুটোই জানা গুরুত্বপূর্ণ, কারণ Linux audit logs-এ UID ব্যবহার হতে পারে।

# 4. Check SSH Login History

`shumon` কখন login করেছে:

# 5. Check SSH Authentication Logs

Ubuntu 22.04-এ সাধারণত SSH authentication log:

```text
/var/log/auth.log
```

`shumon`-এর login activity:

```bash
sudo grep 'shumon' /var/log/auth.log
```

শেষ কয়েকটি entry:

```bash
sudo grep 'shumon' /var/log/auth.log | tail -50
```

Live monitoring:

```bash
sudo tail -f /var/log/auth.log | grep shumon
```

SSH successful login খুঁজতে:

```bash
sudo grep 'Accepted' /var/log/auth.log | grep shumon
```

Failed login:

```bash
sudo grep 'Failed' /var/log/auth.log | grep shumon
```

# 6. Check `sudo` Commands

যদি `shumon` কোনো command-এর জন্য `sudo` ব্যবহার করে, সেটা `/var/log/auth.log`-এ পাওয়া যেতে পারে।

```bash
sudo grep 'sudo' /var/log/auth.log | grep shumon
```

আরও focused:

```bash
sudo grep 'COMMAND=' /var/log/auth.log | grep shumon
```

Example:

```text
shumon : TTY=pts/1 ; PWD=/home/... ; USER=root ; COMMAND=/usr/bin/...
```

এখান থেকে জানা যায়:

* কে command চালিয়েছে
* কোন terminal থেকে
* কোন directory থেকে
* কোন user হিসেবে
* কী command চালিয়েছে

> **Best practice:** Server administration-এর জন্য `sudo` log খুব গুরুত্বপূর্ণ।

# 7. Check Shell Command History

`shumon`-এর Bash history:

```bash

```

শেষ 50 commands:

```bash

```

History count:


> **Important:** `.bash_history` real-time audit system নয়। User history disable করতে পারে, history clear করতে পারে, অথবা কিছু command history-তে নাও আসতে পারে।

তাই sensitive server-এর জন্য শুধু `.bash_history`-এর ওপর নির্ভর করা যাবে না।

# 11. Real-Time Project Monitoring with auditd

Production-level file auditing-এর জন্য `auditd` ব্যবহার করা ভালো।

Install:

```bash
sudo apt update
sudo apt install auditd audispd-plugins -y
```

Service check:

```bash
sudo systemctl status auditd
```

Enable:

```bash
sudo systemctl enable auditd
```

Start:

```bash
sudo systemctl start auditd
```

---

# 12. Audit `shumon` Project Activity

Project-এর file activity track করতে audit rule:

```bash
sudo auditctl -w /home/ai_root/Project/Safty_Automation_Website -p rwxa -k shumon_project
```

এখানে:

```text
-w  → Watch directory
-p rwxa
     r → read
     w → write
     x → execute
     a → attribute/permission change

-k shumon_project
     → Custom audit key
```

---

# 13. Search `shumon` Project Activity

Audit logs search:


আজকের activity:

```bash

```

শুধু `shumon` UID-এর activity:


Human-readable report:

```bash

```

# 14. Make Audit Rule Persistent

`auditctl` rule reboot-এর পরে হারিয়ে যেতে পারে।

Persistent rule তৈরি করতে:

```bash
sudo nano /etc/audit/rules.d/shumon-project.rules
```

Add:

```text
-w /home/ai_root/Project/Safty_Automation_Website -p rwxa -k shumon_project
```

তারপর rules reload:

```bash
sudo augenrules --load
```

Check:

```bash
sudo auditctl -l | grep shumon_project
```

Expected:

```text
-w /home/ai_root/Project/Safty_Automation_Website -p rwxa -k shumon_project
```

# 26. Important Security Notes

### 1. `.bash_history` is not a complete audit

User history clear করতে পারে:

```bash
history -c
```

তাই critical audit-এর জন্য `auditd` ব্যবহার করতে হবে।

### 2. Docker access is powerful

যদি:

```bash
sudo usermod -aG docker shumon
```

দেওয়া হয়, তাহলে `shumon`-এর Docker-এর মাধ্যমে অত্যন্ত privileged access পাওয়া সম্ভব।

### 3. Audit logs protect against history manipulation

`auditd` logs সাধারণ shell history-এর তুলনায় বেশি reliable।

### 4. `.env` files contain secrets

যেহেতু `shumon` project-এর full access পাবে, project-এর:

```text
.env
.env.production
API keys
database credentials
SSH keys
deployment secrets
```

ইত্যাদিও access করতে পারবে যদি সেগুলো project-এর মধ্যে থাকে।

Sensitive secrets আলাদা secret-management system-এ রাখা ভালো।

### 5. Log rotation

Ubuntu সাধারণত system logs rotate করে। তাই long-term audit requirement থাকলে log retention policy আলাদাভাবে configure করতে হবে।
